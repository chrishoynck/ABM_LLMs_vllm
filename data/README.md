# data/ — where every dataset comes from and what it is used for

Almost everything in this folder is **synthetic**: generated by this repo's own
pipelines, with Qwen3.5-27B served through vLLM unless stated otherwise. Only
three inputs are real-world data (first section below); a handful more are
small hand-made seed files. Everything else is derived from those by a script
in `src/` / `scripts/` named in the tables.

This file is the provenance map. Status/cleanup details (what is live vs
historical) live in the per-folder `NOTES.md` files, which each table links to.

```
 REAL DATA                 HAND-MADE SEEDS                GENERATED (synthetic)
 HELIUS PHQ-9 survey  ──►  (persona, PHQ-9) pairs   ──►  post corpora
 PersonaHub/Nemotron  ──►  + generation prompts          (test_post/, finetune/,
 Bathina CDS lexicon ───────────────┐                     sensitivity/, ...)
                                    │                          │
                                    ▼                          ▼
                            distortion metrics          assessors (BERT regressor,
                            in the simulation           optimized PHQ-9 prompt)
                                    │                          │
                                    └──────────► GABM simulation runs (networks_post/)
```

## 1. Real-world data (the only non-synthetic sources)

| File | Comes from | Used for |
|---|---|---|
| `confidential/phq9.sav` | **HELIUS study** — SPSS export of real epidemiological PHQ-9 survey responses. **Confidential: never commit, copy out, or share.** | The empirical, heavy-tailed PHQ-9 distribution that grounds agent initialization (`load_phq9`, [src/llama_activate.py](../src/llama_activate.py) `:356`) and the power-law PHQ-9 figure in the paper and both theses (`experiment.ipynb`). |
| `confidential/phq9_filtered.csv` | Derived from `phq9.sav` by `load_phq9` ([src/utils/tools/load_personas.py](../src/utils/tools/load_personas.py) `:260`): rows with missing `H1_PHQ9_sumscore`/`H1_PHQ9_deprsymp` dropped. Same confidentiality rules apply. | Direct input of the power-law figure. |
| `distorted_language_ngrams.tsv` | **Bathina et al. (2021)**, *Nat. Hum. Behav.* — the cognitive-distortion-schemata (CDS) n-gram lexicon: 241 markers in 12 categories (`categories / markers / variants`). | The distorted-language metric everywhere: per-round distortion fraction in the simulation (`metrics.load_ngrams_tsv`), CDS-vs-PHQ-9 validation (`utils.tools.validate_cds` → `finetune/cds_by_phq9*.csv`), lexical-entrainment analysis, and the paper's cognitive-distortion section. |

No other real human data exists in the repo — **all posts are model-generated**.

## 2. Personas (public HuggingFace datasets + derived pools)

Raw pools come from public persona datasets; all downstream files are
deterministic samples of them built by scripts (source: [src/utils/tools/load_personas.py](../src/utils/tools/load_personas.py), builders in `src/utils/create_data/`).

| File | Comes from | Used for |
|---|---|---|
| `personas_short_10k.csv` | HF **`proj-persona/PersonaHub`** (`persona` split): 10k shuffled sample, English-filtered, quotes normalized (`short_personas()`). | THE main persona pool — simulation agents (`llama_activate.py:352`) and the source every eval/finetune pool below is sampled from. |
| `personas_10k.csv` | HF **`nvidia/Nemotron-Personas`**: 10k shuffled sample, ages 17–79 (`parse_persons()`). | Structured-persona pool (schema with age/occupation/hobbies…); `happy_persona.csv` follows this schema. |
| `personas_eval_1000_phq9.csv` | `utils.create_data.build_persona_phq9_eval` — 1000 personas from the PersonaHub pool (excluding any persona seen in the teacher set) with PHQ-9 targets 0–27 assigned round-robin, fixed seed. | The shared (persona, PHQ-9) anchor set: every model/prompt evaluation and SA generation uses these same pairs so comparisons are paired. Hottest file in `data/`. |
| `personas_finetune_phq9.csv` | `utils.create_data.build_finetune_personas`. | Training personas for the regressor fine-tune (`scripts/assessment/run_finetune.sh`). |
| `finetune/personas_test_extra.csv` | `utils.create_data.build_test_personas` — eval-file rows after the first 120, minus finetune-train personas (no leakage). | Grows the fine-tune test set to 300 blocks. |
| `finetune/personas_unseen_pool.csv` | Built inline by `scripts/assessment/run_bias_calibration.sh` — PersonaHub pool minus every persona used anywhere else. | Balanced, fully unseen personas for the bias-calibration blocks. |
| `happy_persona.csv` | **Hand-written** (1 row, Nemotron schema). | The "happy hub" intervention: the highest-degree agent gets this persona with PHQ-9 pinned to 0 (`llama_activate.py --happy` → `networks_post/happy/`). |

Missing by design: `personas_eval_1000.csv` (the persona-only pool) is a known
dangling default — some code references it but it is not on disk; the
`_phq9` version is the real anchor.

## 5. Data splits — what trains, validates, and tests on what

Published as `tab:datasets` in the PNAS manuscript and as `tab:datasets` +
`tab:optimization_splits` in the CS thesis (Methods); this section maps those
tables to the actual files. A **block** = the 10 posts one persona writes at
one fixed PHQ-9 score.

### Base (teacher) set — assessor training and in-distribution eval

The base set (§4, `test_post/Qwen_Qwen3.5-27B/`) holds **12,000 blocks
(120,000 posts)** — verified on disk: 10k + 20k + 90k CSV rows across the
three seeds.

| Pipeline | Split | Where it lives |
|---|---|---|
| MentalBERT+MLP regressor | **Agent-level 80/10/10** → **9,638 / 1,237 / 1,125 blocks** (train/val/test). Split drawn at runtime by `prompt_optimizer.train_val_test_split` with the run's seed; seeds 34–38 each trained. | Regressors in `test_post/bert_regression/`; the deployed seed-35 test split is materialized as `test_post/bert_regression/test_blocks_seed35.csv` (11,250 rows = 1,125 blocks). |
| LLM-prompt assessor (TextGrad) | Does **not** consume the full split: iterative batched sampling from the base set (train batch n=7 blocks, val ≈40 blocks); only the final eval uses a full held-out test set. | Runs in `test_post/optimized_phq9/`. |

**Alignment caveat:** the two pipelines seed their splits independently, so
they have no shared native test set. For all in-distribution comparisons the
LLM assessor is **re-scored on the seed-35 BERT test blocks** (the 1,125 above),
so both are judged on identical data (`run_phq9_on_bert_testset.sh`).

### Human-optimized corpus — fine-tune and distribution-shift splits

Generated with the iter_10 prompt by `scripts/assessment/run_finetune.sh`
(persona-disjoint by construction, see §2 builders):

| Role | Data | Where it lives |
|---|---|---|
| Fine-tune training | 3,000 personas (`personas_finetune_phq9.csv`) → training posts | `finetune/train_posts.csv` |
| Shared test / shift set | **300 blocks** = 120 pre-existing + 180 newly generated for unseen personas (`finetune/personas_test_extra.csv`) | `finetune/test_posts.csv` (extra half also in `test_posts_extra.csv`; the 120 originate from `prompt_optimization_h/.../SA_prompt/`) |
| Bias calibration | Balanced blocks from fully unseen personas (`finetune/personas_unseen_pool.csv`) → per-level bias table | `finetune/calibration_posts.csv` |

The same 300 blocks double as the **distribution-shift set**: every estimator
(fine-tuned/baseline regressor, optimized and minimal LLM prompt) is re-scored
on them, which is what makes the shift comparison paired
(`run_eval_comparison.sh`, paper row "Assessment, distribution shift").

### Sensitivity analyses — no train/test split, a paired design

Each SA setting generates 60 personas × 10 posts, with every non-varied input
(personas, neighbour posts, per-slot PHQ-9) held fixed across settings:
stochastic axes 4 settings × 3 replicates, PHQ-9 conditioning 5 bands × 3,
decoding 7 settings × 3. Personas come from the shared anchor set (§2), never
from training pools.

> Known 10× slip: the CS thesis Methods prose (and, formerly, this repo's
> README) describes the base set as "≈1,200 blocks / ≈12,000 posts"; the
> on-disk counts and the PNAS split figures (9,638+1,237+1,125 = 12,000
> blocks) show it is 12,000 blocks / 120,000 posts. Fix manuscript-side.

## Caveat that trips people up

The teacher/high-fidelity set (§4 row 1) was generated with the *early*
`prompts_post.json`, while everything downstream of the optimization study uses
the human-optimized prompt — the two post distributions differ, and the
assessment results mix them in documented ways. Full explanation:
[README.md → Known caveat](../README.md#known-caveat--assessment-and-generation-results-come-from-different-datasets).
